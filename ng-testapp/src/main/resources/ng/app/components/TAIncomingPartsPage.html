File upload: incoming parts

A form is uploaded as a multipart request: its fields and files arrive as a sequence of parts. Usually the framework collects the whole request before your code runs, as the other upload pages do. For very large uploads, a direct action or route can instead read the parts as they arrive, never keeping more than a small buffer of the upload in memory or on disk: 

if( request() instanceof NGMultipartRequest request ) {
	for( Part part : request.incomingParts() ) {
		part.stream().transferTo( storage );
	}
}

A part's stream is readable until the next part is asked for, and the parts can be read once. Collecting (formValues(), uploadedFiles()) and reading as they arrive exclude each other, so a handler reading incoming parts gets the form's fields as parts too. The query string's values are still in formValues(), like the folder this form posts with. Component actions always collect, since a form's elements need all its values, which is why this form posts to a direct action, DirectAction.incomingPartsAction().
